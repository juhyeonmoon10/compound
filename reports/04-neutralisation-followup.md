# 4절 후속 — 공식 타이밍 기반 SC·VSC 자료와 소비 연결

작성일: 2026-09-07. 대상은 현재 작업 트리의 자료 수집기, 요약 생성기, 확률 실험 소비자와 집중 테스트다. 이전 `04-race-experiments.md`의 “공식 빈도 별도 수집 예정”을 보완한다. 브라우저 최종 통합 검수·배포 완료를 뜻하지 않는다. 이 담당 작업에서는 커밋·푸시를 하지 않았다.

## 결과와 분모

2018–2025년 결승 **173경기**에 대해 공식 타이밍 스트림을 실제 요청했다. 스프린트·테스트는 제외했다. **137경기는 빈도 집계 가능, 36경기는 제외**했다. 결측이나 예외 경기를 SC/VSC 0회로 바꾸지 않았다.

| 제외 사유 | 경기 수 | 처리 |
| --- | ---: | --- |
| 2018 전반 12경기: 레이스 시작 시점 TrackStatus 초기 상태 없음 | 12 | 뒤에 기록된 부분 구간은 보존하지만 전체 경기 발생률 분모에서는 제외 |
| 2020 아이펠: 동일한 초기 상태 누락 | 1 | 부분 관측과 전체 경기 빈도를 구분 |
| 2021 벨기에: Started→Aborted→Finalised, Finished 없음 | 1 | 특수 중단 경기를 정상 경기의 무사고 0으로 집계하지 않음 |
| 2022년 전체: 공식 서버 HTTP 403 | 22 | 접근 제한 우회 없이 요청 URL·실제 오류 보존 |
| 합계 | 36 | 173−36=137 |

2021 스파는 특히 TrackStatus에 SC 코드 4가 없었다. 이를 “SC가 없었던 경기”로 해석하지 않았다. 공식 SessionStatus와 레이스 컨트롤 기록에서 특수 절차를 확인했고, 정상 레이스 종료 기준을 충족하지 않는 제외 사례로 남겼다.

현재 UI의 24개 서킷을 모두 매핑했다. 마드리드는 해당 기간 개최 자료가 없어 관측 확률은 null이다. 사키르 외곽 레이아웃은 바레인 GP 레이아웃과 합치지 않았다. 과거에만 열린 다른 서킷들도 원자료에 별도로 남겼다.

유효 5경기 이상인 **15개 서킷**은 관측 빈도를 채택할 수 있다: 스즈카, 바레인, 모나코, 바르셀로나, 스필버그, 실버스톤, 스파, 헝가로링, 몬차, 바쿠, 싱가포르, 오스틴, 멕시코시티, 상파울루, 야스마리나. 나머지 9곳은 관측값을 보존하되 실행 확률은 프로젝트 기본값으로 대체한다.

## 공식 기록과 프로젝트 계산의 경계

사용 채널은 `TrackStatus.jsonStream`, `LapCount.jsonStream`, `SessionStatus.jsonStream`, `WeatherData.jsonStream`, `RaceControlMessages.jsonStream`이다. 랩 전체·차량 텔레메트리는 이 작업에서 새로 불러오지 않았다. API 경로는 FastF1 3.8.3의 일정·세션 경로를 사용했지만 실제 집계 대상은 `livetiming.formula1.com` 응답이다.

- 코드 4는 SC, 6은 VSC. 바로 이어진 7은 VSC 종료 준비 상태로 같은 구간에 병합한다. 7만 있는 불완전 구간은 제외한다.
- 첫 Started부터 첫 Finished까지만 사용하고, Aborted부터 재시작까지는 활성 주행 구간에서 뺀다. 종료 후 상태 변경은 계산하지 않는다.
- 레이스 컨트롤에 DEPLOYED가 있는데 해당 상태 구간이 전혀 없으면 자료 충돌로 제외한다. 이 검사는 모든 메시지·상태의 완전한 일대일 검증은 아니다.
- 빈도는 `한 번 이상 해당 상태가 있었던 유효 경기 / 전체 유효 경기`다. 랩당 사고 위험률이나 경기당 평균 사고 횟수가 아니다.
- 지속 랩은 상태 구간과 겹친 선두 LapCount 구간의 수다. 부분 랩도 포함한다. 실제 초 단위 길이와 부분 랩 환산을 별도로 보존한다. 랩 카운터 누락·역행 때는 빈도와 별개로 지속 랩을 null로 남긴다.
- Rainfall은 기상 관측의 참/거짓 값이다. 강수 강도·노면 수막을 측정하지 않는다. 기상 갱신을 최대 180초까지 이어 쓰는 것은 프로젝트 품질 기준이다. 미확보 구간, 비와 겹친 구간, 레드플래그로 끝난 구간은 별도 기록한다.
- SC·VSC는 같은 TrackStatus에서 동시에 발생할 수 없으며 둘의 전환은 별도 구간이다. 레드 상태는 별도 집계한다.
- 제공한 비율은 **공식 타이밍을 분석한 프로젝트 관측 빈도**다. FIA나 Pirelli가 발표한 예측 확률 표가 아니다.

출처 예시: [2018 호주 TrackStatus](https://livetiming.formula1.com/static/2018/2018-03-25_Australian_Grand_Prix/2018-03-25_Race/TrackStatus.jsonStream), [2021 벨기에 SessionStatus](https://livetiming.formula1.com/static/2021/2021-08-29_Belgian_Grand_Prix/2021-08-29_Race/SessionStatus.jsonStream), [2022 바레인 요청 URL — 수집 시 403](https://livetiming.formula1.com/static/2022/2022-03-20_Bahrain_Grand_Prix/2022-03-20_Race/TrackStatus.jsonStream). 전체 채널 URL과 실패 이유는 원자료에 있다. 상태 코드 설명은 설치된 FastF1 3.8.3 소스와 [FastF1 문서](https://docs.fastf1.dev/api.html#fastf1.api.track_status_data)를 기준으로 확인했다.

## 상수·채택·대체 규칙

| 상수/입력 | 값 | 근거·의미 |
| --- | --- | --- |
| `race.minObservedRaces` | 5경기 | 새로 추가한 프로젝트 최소 빈도 표본 기준. FIA 기준 아님 |
| `race.minDurationEpisodes` | 3구간 | 새로 추가한 프로젝트 최소 지속 랩 표본 기준. 종류별 독립 검사 |
| 기본 SC/VSC 확률 | 0.35 / 0.25 | 기존 프로젝트 사전값. 관측 미연결·표본 미달 때만 실행 입력으로 사용 |
| 기본 SC/VSC 지속 랩 | [2,3,4,5] / [1,2] | 기존 프로젝트 분포 |
| 시작 위치 범위 | 레이스 8%–90% | 기존 프로젝트 위치 가정. 관측 시작 랩 분포를 학습한 값 아님 |
| SC/VSC 피트 비용 배수 | 0.55 / 0.70 | 기존 프로젝트 할인. 실측 정차 시간 또는 공식 피트 델타 아님 |
| 발생 비율 95% 구간 | Wilson 이항 구간 | 표본 불확실성 계산. 미래 경기 또는 완주 시간의 예측 구간 아님 |

빈도와 기간의 채택은 독립이다. 예를 들어 제다는 4경기라 확률은 기본값을 사용하지만 SC 지속 랩은 4구간을 확보해 경험 분포를 사용할 수 있다. 모나코는 빈도 5경기를 충족하지만 종류별 기간 표본이 부족해 지속 랩은 기본값을 사용한다. 현재 서킷 중 SC 기간은 16곳, VSC 기간은 10곳이 기간 표본 기준을 충족한다.

관측 0은 null과 다르다. 스파 VSC의 0/6은 관측 확률 0으로 유지한다. 마드리드의 0개 표본은 관측 확률 null이며, 실행할 때만 35%/25% 사전값을 쓴다. 0/n의 상한 신뢰구간은 양수이므로 실제 발생 가능성이 영원히 0이라는 주장은 하지 않는다.

`getNeutralisationPrior`는 실행 확률과 optional `scDurations`/`vscDurations`, `evidence`를 반환한다. `evidence`에는 원 관측 확률·분자·분모·95% 구간·종류별 채택 여부·기간 표본·설명이 있다. 제공 기간 배열은 비어 있지 않은 정수 1…레이스 랩 수로 검사한다. 경험 표본은 중복값도 유지해 빈도를 보존하며 완주 시점에서 임의로 잘리지 않도록 시작 위치를 제한한다. 기본 분포 경로의 기존 난수 결과는 보존했다.

## 테스트와 통합 범위

실행한 집중 검사:

```text
node --experimental-strip-types --test --test-isolation=none tests/neutralisation-prior.test.mjs tests/race-experiments.test.mjs tests/race-experiment-worker.test.mjs
```

- 27 PASS / 0 FAIL. 단위 테스트, 실제 TSX 근거 렌더, 실제 TypeScript Worker 왕복 포함.
- 기본 시드 20260906의 300시행에서 SC 108회라는 기존 성질 유지.
- 실제 관측 0/null, 종류별 게이트, 원자료→요약 일치, 잘못된 기간, 전체 레이스 길이의 기간, 경험 분포 재현성 검사 통과.
- 선택 사전값을 Worker에 전달하고, 사전값 변경 시 기존 Worker 종료·늦은 응답 거부·다른 사전값을 담은 응답 거부 검사 통과.
- 수집 checker의 합성 구간/부호/경계 검사와 173경기 분모·기간·예외·원시/compact 일치 검사 통과. 해당 TypeScript/TSX/tests ESLint 통과.
- 소비 연결 직후 전체 TypeScript 검사는 다른 병행 작업의 `RaceReplay`/`StrategyLab` 우천 nullable 표시 연결 오류 15건 때문에 실패했다. 이 담당 파일의 타입 오류는 없었지만, 그 시점의 전체 타입 검사를 통과로 기록하지 않는다. 최종 통합 결과는 루트 검증으로 별도 확인해야 한다.
- 초기 읽기 점검에서 main의 사전값 prop이 없음을 발견해 전달했다. 이후 주 작업자가 `StrategyLab` import·`useMemo(() => getNeutralisationPrior(applied.trackId), …)`·Panel의 `eventPrior` 연결을 완료했다고 확인했다. 같은 담당자의 후속 핵심 DP·우천 포함 집중 검사 결과는 63/63 PASS다. 이는 앞선 27개와 겹치는 별도 실행이므로 합산하지 않는다. 최종 브라우저 검증은 9절에서 별도로 기록한다.

## 아직 구현하지 않은 것

1. 실제 SC 주행 감속, 전체 랩 지연, 대열 압축, 랩다운 차량 해제, 재출발 페이스를 계산하지 않는다. 현재 사건은 피트 비용 할인과 추월 제한에 반영한다. 3D 자동차가 실제 SC 속도로 느려진다고 설명하면 안 된다.
2. 한 시행에 SC·VSC 각각 최대 한 구간만 만든다. 실제 한 경기 다중 사고나 사건 간 의존성을 재현하지 않는다. 두 구간이 겹치지 않는 자리가 없으면 뒤 구간을 생략하므로 실행 중 나타나는 빈도가 입력 사전확률과 정확히 같지 않을 수 있다.
3. 과거 시작 랩을 수집했지만 현재 발생 시작 시점은 8%–90%의 가정 범위에서 난수 선택한다. 시작 직후 사고·마지막 랩 사건의 실제 분포를 학습하지 않았다.
4. 2018–2025의 레이아웃·규정·날씨 차이, 2022 전체 결측 및 초기 기록 누락에 따른 선택 편향이 남는다. 현재 날씨·팀·실시간 사건에 조건부로 확률을 갱신하지 않는다.
5. 관측 사전값을 사용해도 전체 모형은 프로젝트 추정 운영 모형이다. SC/VSC까지 포함해 DP를 다시 최적화하지 않으며, 이미 만든 후보를 공통 상황에서 비교한다.
6. 단위·Worker 검사 통과는 실제 F1 예측 정확도나 픽셀/3D 시각 완성도의 증거가 아니다.

당시 정제 표본은 호주 547랩(슬릭 36/인터 511), 영국 435랩(138/297), 벨기에 681랩(549/132)이었다. WET 비교 표본은 없었다. 영국 L9 음수 차이에서 L40 양수 차이로 바뀌지만 중간 30랩의 동시 표본이 없으므로 정확한 전환 랩을 추정할 수 없다.

FastF1의 실제 조인은 랩 구간 안 첫 기상 샘플을 쓰고, 없으면 해당 랩 종료 전 마지막 샘플을 쓴다. 기상 관측은 보통 분 단위다. 인접 샘플 보간이나 동일 시각 차량 매칭으로 설명하지 않았다.

추가로 확인한 보완 필요 사항은 우천 JSON에 개별 경기 timing URL이 없는 점, 건식 회귀/5랩/IQR 공통 메타가 우천 자료에도 붙어 실제 우천 정제와 혼동되는 점이다. 또 당시 `rainfallTrue=eq(True).any()`는 전체 결측을 false로 만들 가능성이 있었다. 현 스냅샷의 `rainfallKnownLaps==laps`여서 현재 값이 잘못됐다는 증거는 없지만, 미래 결측을 “비 없음”으로 보여주지 않도록 구분해야 한다.
