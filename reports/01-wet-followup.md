# 1절 후속 — 우천 관측 분포와 실제 타이어 전환 기록

작성일: 2026-09-07. 기존 2025 호주·영국·벨기에 FastF1 캐시를 재사용한 자료·UI·집중 테스트 보완이다. 네트워크 재수집이나 다른 데이터셋 재생성, 모델의 실측 보정, 최종 브라우저 검수·배포 완료를 뜻하지 않는다. 이 담당 작업에서 커밋·푸시는 하지 않았다.

루트 후속 확인: 기존 알고리즘·우천 DP 및 관측 UI를 함께 재실행해 **41 PASS, 0 FAIL**, 프로덕션 빌드 PASS. 실제 브라우저에서 영국 L8 −2.342초(슬릭6/인터11대), L9 −6.186초(5/10대), L40 +2.056초(2/7대), L41 +0.714초(2/6대)를 점과 숫자로 확인했다. 모바일 390px에서 문서/가용 너비 375px 일치, 콘솔 오류·경고 없음. 실제 전환 31/23/20건과 원문 링크도 표시된다. 이는 관측 UI 검수이며 실측 교차 수막 보정 완료를 뜻하지 않는다.

## 확보한 결과

기존 동랩 비교 **5개를 값·랩·양쪽 차량 표본 수까지 그대로 보존**했다. 경기별·타이어 쌍별로 최소/Q1/중앙값/Q3/최대와 개별 관측점을 추가했다. 실제 슬릭↔인터 전환 **74건**을 기존 타이밍 캐시에서 확인했다. 모두 인접한 두 랩에서 종류·스틴트가 바뀌고, 피트 인 또는 아웃 시각 표지가 있었다. 이는 기록된 결정이지 최적 교체 시점의 정답이 아니다.

| 2025 결승 | 정제 슬릭 랩 | 정제 인터 랩 | 정제 웨트 랩 | 동랩 비교 | 실제 종류 전환 | 피트 시각 표지 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 호주 | 36 | 511 | 0 | 1 | 31 | 31 |
| 영국 | 138 | 297 | 0 | 4 | 23 | 23 |
| 벨기에 | 549 | 132 | 0 | 0 | 20 | 20 |

위 표의 웨트 0은 해당 정제 스냅샷에서 보유한 표본 수이며, 웨트의 성능·효과가 0이라는 뜻이 아니다. 인터–웨트 동랩 비교는 모두 0개다. 전체 우천 요약의 `supportsWetCrossoverCalibration`은 계속 `false`, `calibrationStatus`는 `project-estimates-retained`다.

## 개별 점과 분포

차이는 **슬릭 차량 랩타임 중앙값 − 인터 차량 랩타임 중앙값**이다. 양수이면 해당 관측점에서 인터 표본이 빨랐다. 같은 랩 번호라도 각 차량의 벽시계 시각은 다를 수 있다.

| 경기 | 랩 | 차이(초) | 슬릭/인터 차량 표본 |
| --- | ---: | ---: | ---: |
| 호주 | 46 | +6.367 | 4/6 |
| 영국 | 8 | −2.342 | 6/11 |
| 영국 | 9 | −6.186 | 5/10 |
| 영국 | 40 | +2.056 | 2/7 |
| 영국 | 41 | +0.714 | 2/6 |

| 경기 | n | 최소 | Q1 | 중앙값 | Q3 | 최대 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 호주 | 1 | 6.367 | 6.367 | 6.367 | 6.367 | 6.367 |
| 영국 | 4 | −6.186 | −3.303 | −0.814 | 1.050 | 2.056 |

단위는 초. 분위수는 NumPy 기본 선형 보간 방식이고 세 자리로 반올림했다. 한 점짜리 호주 분포는 모든 요약값이 같다. 영국 네 점의 사분위 범위는 작은 표본의 산포이며 예측 신뢰구간이 아니다. 서로 다른 경기를 합친 평균이나 분위수를 만들지 않았다.

영국에서 L9의 −6.186초(5/10대) → L40의 +2.056초(2/7대)로 관측 부호가 바뀐다. 두 끝점의 강수 플래그는 모두 false다. **중간 30개 랩에는 해당 동랩 비교가 없으므로 정확한 전환 랩은 `null`**이다. 이 구간을 최적 피트 창, 수막 전환점, 단일 원인의 효과라고 표시하지 않는다. 강수 미관측은 마른 노면을 증명하지 않는다.

## 공식 타이밍 출처와 조인

각 이벤트에 아래 정확한 공식 경기 경로를 저장하고, 화면에서 `SessionInfo.json`, `WeatherData.jsonStream`, `TimingAppData.jsonStream` 링크를 제공한다. 이번 실행은 이미 저장된 공식 타이밍 응답을 FastF1로 파싱했으며 링크의 재접속 성공을 새로 주장하지 않는다.

- 호주: https://livetiming.formula1.com/static/2025/2025-03-16_Australian_Grand_Prix/2025-03-16_Race/
- 영국: https://livetiming.formula1.com/static/2025/2025-07-06_British_Grand_Prix/2025-07-06_Race/
- 벨기에: https://livetiming.formula1.com/static/2025/2025-07-27_Belgian_Grand_Prix/2025-07-27_Race/

각 차량 랩에 FastF1 `get_weather_data()`의 랩 안 첫 기상 샘플을 연결하고, 그 랩에 없으면 랩 종료 전에 있는 마지막 샘플을 사용한다. 분 단위 표본을 임의로 보간하지 않는다. 강수 여부·노면 온도·습도의 확보 수와 선택된 기상 샘플부터 랩 종료까지의 시간차를 이벤트별로 남겼다.

| 경기 | 정제 랩 | 강수/노면 온도/습도 확보 랩 | 기상 샘플→랩 종료 시간차 범위(초) |
| --- | ---: | --- | --- |
| 호주 | 547 | 547/547/547 | 30.391–97.689 |
| 영국 | 435 | 435/435/435 | 32.705–108.632 |
| 벨기에 | 681 | 681/681/681 | 46.313–123.041 |

시간차는 **조인의 시간 간격**이며 센서 통신 지연이나 노면 건조 시간을 측정한 값이 아니다. 전체 강수 표본이 결측이면 `null`; true가 하나라도 있으면 true; 모든 값이 알려져 있고 false일 때만 false로 요약한다. false와 unknown이 섞이면 unknown으로 보존한다.

## 정제와 전환 추출은 구분

- 우천 랩 비교는 `IsAccurate`, 삭제·생성 여부, 녹색기, 유효 랩타임, 첫 랩 제외, 피트 인/아웃 제외를 적용한다. 종류가 불명인 랩은 제외하고 S/M/H를 슬릭 그룹으로 묶는다.
- 이 요약에는 건식 회귀의 최소 5랩 스틴트, IQR 필터, 회귀 보정, 홀드아웃 평가를 적용하지 않는다. 기존 건식 방법 설명을 우천에도 적용한 것처럼 쓰던 메타데이터를 우천 전용 설명으로 분리했다.
- 실제 전환 추출은 피트 랩을 없애면 근거를 잃으므로 별도 원시 랩 경로를 사용한다. 선수별 인접한 랩, 알려진 종류·스틴트, 생성 랩 아님, 타이어 그룹·스틴트 변화로 추출하고 피트 시각 표지를 별도 기록한다.
- 인접하지 않거나 스틴트가 바뀌지 않는 이상 사례는 확정 전환으로 계산하지 않고 `unresolvedTyreChangeGaps`에 남긴다. 현재 세 경기의 미해결 간격은 0건이다. 합성 테스트에서는 이러한 불완전 사례가 정상 전환과 분리되는지 확인한다.
- 전체 종류별 랩타임 분포도 제공하지만, 서로 다른 레이스 구간·타이어 수명·선수·교통 상황을 섞으므로 타이어 고유 효과라고 해석하지 않도록 화면에 경고한다.

FastF1 캐시 재생 중 호주 일부 선수 및 벨기에 스틴트 정정 경고가 있었다. 영국 43번 선수는 정확성 판정 경고가 있어 정제 비교에서 제외된다. 실제 전환은 FastF1이 파싱·정정한 기록에 근거하며 별도의 원시 메시지 수작업 재구성이 아니다. UI에도 스틴트 정정 가능성을 표시한다.

## 구현 파일과 재현

- `app/WetEvidencePanel.tsx`: 경기별 접기 영역, 표본·분포·개별 점 5개, 공식 링크, 실제 교체 목록, 조인·정제·보정 한계 표시. 작은 화면에서 표와 관측점은 자체 가로 스크롤을 사용한다. 표 머리글·스크롤 영역·SVG 설명을 제공한다.
- `app/data/wet-weather-2025.json`: 기존 비교 5개를 보존하면서 분포·전환 74건·출처·날씨 조인·수집 상태 추가.
- `tools/collect_historical_evidence.py`: 우천 전용 방법 설명과 순수 계산 함수, `--wet-only-from-cache` 경로 추가. 건식 계산을 재실행하지 않는다.
- `tests/wet-evidence.test.mjs`: 저장 관측점·독립 분위수 계산·희소 부호 변화·원자료 및 표본·실제 React 렌더·강수 unknown 검증 5개.
- `tools/test_wet_evidence.py`: 분위수, 강수 결측, 경기/타이어 쌍 분리, 부호 변화의 희소 간격, 실제 전환의 인접성·피트 표지·누락 간격 합성 검사.

일반 Python 환경에서 FastF1 의존성을 설치하고 기존 캐시가 있을 때:

```sh
python tools/collect_historical_evidence.py --wet-only-from-cache --cache-dir work/fastf1-cache
python tools/test_wet_evidence.py
node --experimental-strip-types --test tests/wet-evidence.test.mjs
```

`--wet-only-from-cache`는 기존 우천 JSON을 먼저 읽고 FastF1 오프라인 모드와 HTTP 전송 차단을 함께 사용한다. 캐시 미확보 또는 기존 비교값 불일치 시 저장 비교를 보존하고 `actualTyreChanges: null`과 실제 실패 사유를 남긴다. `--output-dir`의 우천 JSON만 갱신한다. 캐시는 저장소에 포함되지 않으며 재현자가 직접 가진 캐시 위치를 지정해야 한다.

이번 실행 환경은 번들 Python에 기존 `work/fastf1-pkg`를 import 경로로 주입하고 원 프로젝트의 `work/fastf1-cache`를 지정했다. 새 패키지를 설치하지 않았고 모든 세션이 캐시 재사용으로 완료됐다. 스냅샷 갱신 시각은 `2026-09-07T01:11:05.610676+09:00`, 보존한 기존 관측 스냅샷 시각은 `2026-09-06T23:28:12.50296+09:00`이다.

## 검증 결과와 남은 제한

- 우천·기상·역사 보정 집중 Node 테스트 **19/19 통과**. 우천 신규 테스트는 그중 5개다.
- 우천 순수 함수 Python 합성 검사 통과. 외부 통신·세션 로드 없이 실행했다.
- `tsc --noEmit` 통과. 우천 TSX와 테스트 파일 ESLint 통과.
- 전체 앱의 최종 테스트·실제 브라우저 검수·배포는 루트 에이전트의 별도 검증 대상이다. 위 수치는 전체 프로젝트 합격 수치가 아니다.

강수량·수막 깊이·타이어 온도·그립 직접 센서가 없고, 전체 웨트 및 인터–웨트 비교가 부족하다. 따라서 수막 0.10/0.60 같은 모델 경계를 실측 학습값으로 바꾸지 않는다. 같은 랩 비교도 서로 다른 차량·선수·교통·타이어 수명과 미세한 시각 차이를 통제하지 못한다. 실제 교체 74건은 선택의 관측이지 교체가 최적이었다는 검증이 아니며, 경기별 1개 또는 4개 차이의 분포만으로 일반화 성능이나 확률 신뢰구간을 만들지 않는다.
