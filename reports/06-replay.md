# 6절 · 레이스 기록과 전략 리플레이

## 변경 파일과 연결

- `app/RaceReplay.tsx`: `ReplayTelemetry`를 주행 전체화면 대상인 `viewportRef` 바깥, 리플레이 섹션의 직접 자식으로 연결했다. 기존 `raceGridData.grid`, `gridFrame`, `driver.id`를 그대로 전달한다. 출발 대기·카운트다운은 `hasStarted=false`이다. 선택 실험은 선택적 `experimentTimeline?: RaceExperimentTimeline | null`로 받는다.
- `app/ReplayTelemetry.tsx`, `app/replay-telemetry.css`: 전체 20대 순위 / 스틴트 기록 / 레이스 이벤트 탭. 한국어 선수명·상태·격차 단위, 내 차 굵은 이름과 강조, 5종 타이어 의미 색상을 제공한다. 피트는 랩 종료 경계의 마름모로 표시한다. 전달된 SC/VSC 구간만 20대 스틴트 행에 반투명 띠로 표시하며, 범례와 별도 원기록에 **확률 실험 조건 · 재생 시계 미반영**을 명시한다.
- `app/lib/replay-telemetry.ts`: 기존 그리드 프레임으로 순위·선두 격차·앞차 격차·사용 완료 랩을 산출한다. 출발·피트 진입/복귀·성능 급락·완주 로그는 실제 조정된 리플레이 구간의 시각을 쓴다. 현재 재생 시각 뒤의 이벤트는 숨긴다. 언더컷은 기존 정산 함수를 호출하고 두 차량 모두 정산 랩을 마친 후에만 공개한다.
- `tests/replay-telemetry.test.mjs`, `tests/replay-telemetry-ui.test.mjs`: 순수 계산, 실제 TSX 서버 렌더링, TypeScript AST 구조 검사. 랩타임 비교 차트는 이 패널에 중복 추가하지 않았으며 상위 화면의 접힌 상세 차트로 분리한다.

## 상수와 데이터 출처 구분

- 새 전략·물리 상수를 추가하지 않았다. 타이어 색/명칭은 `app/model/params.ts`의 `TYRE_COLORS`, `TYRE_LABELS`를 그대로 참조한다. 팀 강조색은 타이어색과 별개다.
- 언더컷 정산 기간은 기존 `MODEL_PARAMS.race.undercutSettlingLaps`(3랩), 성공 기준은 기존 `assessUndercut`의 `minimumDistinctSeconds`(0.5초)를 사용한다. 모두 프로젝트 계산 규칙이지 실측 확률이 아니다.
- 실제 선수명은 현재 참가자 22명의 ID를 한국어로 대응한다. 화면에는 기존 리플레이가 구성한 20대가 표시되며, 2026 실제 출전 22대를 모두 재현한다는 뜻이 아니다.
- CSS의 표 높이·간격·선 두께와 안전 차량 띠 색은 표시용 값으로 레이스 계산에 사용하지 않는다.

- 루트 추가 검사: 기존 알고리즘 30개(건식 DP ↔ 완전탐색 포함) + 우천 6개(3스톱 DP ↔ 완전탐색 포함) **36 PASS, 0 FAIL**. 기록 패널 13개도 재실행 PASS. 최초 명령의 잘못된 파일명으로 핵심 검사 36개가 실행되지 않은 것을 확인하고 정확한 파일명으로 다시 실행했다.

- `StrategyLab.tsx`의 재생 랩타임 차트는 고유 접근성 ID를 사용하며 수막 오른쪽 축 0·0.5·1, 비 구간 음영을 포함한다. `params.chart`에 도표 크기·여백·눈금을 표시용 상수(px/수막 단위)로 모았다. 이 검사는 병렬 수정 중 작업 트리 기준이며 최종 전체 검사는 9절에서 반복한다.

## 한계

- SC/VSC 띠는 300회 확률 실험 중 전달받은 시행의 랩 조건을 설명하는 오버레이다. 3D의 주행 시계·순위에는 SC/VSC 피트 할인이나 감속이 적용되지 않는다. 임의 안전 차량 이벤트를 생성하거나 확률 실험과 리플레이의 최종 결과가 같다고 주장하지 않는다.
- 레이스 데이터는 자동 주행 모델 출력으로 실제 실시간 타이밍이 아니다. 차량 물리·추월 경로·정확한 고도는 재현하지 않는다. 실제 주행 능력을 평가하는 게임도 아니다.
- 타이어 사용량은 현재 부분 랩을 제외한 완료 랩이다. 스틴트의 흐린 후반부·피트 마커는 계획이며, 과거 이벤트 로그와 구분한다. 종료 직전 피트처럼 정산 랩이 부족한 언더컷은 성공 판정을 내지 않는다.
- 표와 스틴트는 작은 화면에서 패널 내부 가로 스크롤을 사용한다. 실제 화면 넘침과 스크롤 조작성은 9절에서 확인해야 한다.
