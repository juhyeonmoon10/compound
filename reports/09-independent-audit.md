# 독립 코드 검수 · 수식, 데이터 근거, 표시 의미

검수일: 2026-09-07. 대상: 현재 `compound` 공개용 저장소의 계산 모듈, 근거 패널, README. 사용자 제공 0–9절 요구서를 전체 확인하고 검수했다. 화면의 픽셀 검수나 최종 배포 검수와는 별개의 코드·근거 검수다.

검수 시점에 주 작업자가 진행 중이라고 알린 날씨·성능 속성 연결, 리플레이 정보 복구, 검증 패널·백테스트 지연 로딩, 실험 노트 조건 전달은 미구현 버그 목록에 중복 산입하지 않았다. 별도 작업 중인 SC 통계와 공유 20대 그리드도 최종 완료 여부를 이 문서에서 단정하지 않는다.

## 확인한 오류와 조치

### 1. 강수 프리셋이 건식 2종 규칙을 무조건 면제함 — 수정 완료

- 위치: `app/lib/strategy-backtest.ts`, `createBacktestInput`.
- 원인: `requireTwoDryCompounds: weather.preset === "none"` 때문에 비가 있는 입력의 모든 전략이 면제됐다. 수정된 공통 엔진과 화면의 규칙 설명은 실제 INTER/WET 사용 여부를 검사하므로 백테스트만 다른 규칙을 사용하고 있었다.
- 재현: 영국 2025 입력에서 S 1–20랩 → S 21–40랩 → S 41–52랩이 이전에는 합법이었다. 같은 입력에서 규칙을 켜면 건식 1종만 사용해 불법이다.
- 수정: 백테스트도 `requireTwoDryCompounds: true`를 유지한다. 공통 엔진이 실제 INTER 또는 WET 사용을 확인해 예외를 적용한다. 강수만으로 면제하지 않는다.
- 회귀 검사: S-S-S는 불법, 첫 세트를 INTER 또는 WET으로 바꾸면 합법. 기존 7경기·21명·9개 기존 전략 보존과 재현성 검사도 통과했다.

### 2. 대표 대안을 전역 2·3위로 오해할 수 있는 설명 — 보드 보완 확인, 문서 확인 필요

- `buildRepresentativeStrategies`는 전역 최단 전략을 보존하고, 그룹별 최단 및 피트 경계 하나를 이동한 후보에서 구분 가능한 대안을 고른다. 전역 K-best의 2·3위 자체를 보장하는 함수는 아니다.
- 기존 K-best 계산 함수는 그대로 유지돼 있다. 대표 후보 구성은 요구된 중복 제거·0.5초 간격을 위한 별도 표시 방식이므로 계산 방식 자체를 오류로 보지 않았다.
- 검수 중 보드에 “1번은 최단 해, 2·3번은 대표 대안이며 전역 2·3위가 아님”이라는 설명이 추가된 것을 확인했다.
- 검수 시점 README 첫 설명에는 아직 단순 “상위 3개” 표현이 남아 있다. 최종 문서에도 최단 전략과 대표 대안을 구분하면 의미가 일치한다.

### 3. 저장 실험의 학습 연도 라벨 — 수정 요청 전달

- 위치: `app/ExperimentNotebook.tsx`, 계수 모델 비교 행.
- 내부 호환 식별자 `fastf1-2025`는 유지해도 되지만, 화면의 “FastF1 2025 학습 계수”는 현재 2023–2025 풀링 계수와 다르다.
- 제안: 기존 v1 기록의 정확한 수집 버전을 임의로 확정하지 않도록 “FastF1 관측 보정 계수”처럼 표기하거나 기록 버전에 맞춰 구분한다. 식별자 자체를 변경할 필요는 없다.

### 4. 젖은 타이어 상태 표시가 과열 비용과 상충함 — 수정 완료

- 위치: `app/lib/tyre-state.ts`의 INTER/WET 반환, 상세 랩 표의 온도·그립·상태 표시.
- 재현: 물이 없는 노면에서 INTER 10랩을 계산하면 10번째 랩의 수막·과열 비용은 5.75초, 선형 마모는 1.08초다. 그러나 상태 객체는 항상 “최적”, 그립 100%, 온도 65°C를 반환한다. 무제한 스틴트 한도를 분모로 사용해 마모율도 사실상 0%가 된다.
- 랩타임의 과열 누적은 계산되고 있으므로 총시간 오류는 아니다. 실제 수막·타이어 관리 상태처럼 읽히는 표시가 문제다.
- 수정: INTER/WET의 온도·적정 온도 범위·그립·마모율을 `null`로 반환해 미모델링임을 데이터 자체에서 구분한다. `modelKind="wet-heat-only"`와 `wetDryLaps`를 추가했다. 기존 엔진이 비용 계산에 사용하는 실제 건조 이력을 전달하며, 누적 건조 랩이 있으면 과열, 없으면 “과열 누적 없음” 상태로 구분한다. 온도는 역산하거나 임의 생성하지 않는다.
- 과열 비용은 기존 `wetPenalty`에 이미 포함돼 있으므로 `tyreState.totalStateLossSeconds`는 계속 0이다. 시간식을 변경하거나 같은 비용을 두 번 더하지 않았다. 피트 교체 시 건조 이력이 초기화되고, 다시 젖어도 기존 모델에 남는 누적 과열 이력과 상태가 일치한다.
- `formatTyreStateMetric`은 null을 한국어 “미모델링”으로 출력하며 실제 수치 0과 구분한다. 주 작업자가 `StrategyLab`의 표·라벨을 연결했고, 이 검수 담당자는 허용된 시점 이후 `RaceReplay`의 HUD·음성 설명·상세 수치를 연결했다. HUD의 G/W를 그립/마모로 바꾸고 우천 수치를 미모델링으로 표시한다. 상세에는 이전 건조 랩 수의 과열 비용 모델 설명과 수막·과열 비용 항목을 구분해 표시한다.

## 요구서의 수치·표현을 그대로 따르지 않은 이유

- 제시된 우천 식의 슬릭→인터 경계는 수막 0.10 바로 위의 불연속 전환이다. 0.12가 두 식의 교점이라는 설명은 맞지 않는다. 인터→웨트 교점은 0.60이다. 0.55에서는 두 식이 아직 같지 않다.
- 비가 오는 프리셋 자체와 실제 INTER/WET 사용은 같은 규칙 조건이 아니다. 공통 엔진의 실제 사용 판정을 백테스트에도 일치시켰다.
- “검증된 값”으로 전달된 기존 표본 수, MAE, 실버스톤 기준 랩·오차는 재수집 결과로 확인되지 않았으므로 복사하지 않았다. 현재 원자료와 재현 스크립트가 산출한 값이 근거다.
- β 유의성은 부드러운 2차 열화의 근거이지, 급격한 클리프 시작 랩을 식별한 결과가 아니다. 현재 클리프 임계점과 비선형 타이어 상태 계수는 프로젝트 가정이며, “클리프 시작 랩 실측 학습 완료”로 보고하면 안 된다.
- 2025 백테스트 경기 일부가 계수 보정 자료에도 포함된다. 이는 독립 미학습 경기 검증이 아니며, 그 한계가 표시돼 있다. 영국의 큰 전체시간 오차를 SC·재출발 오차 보정으로 숨기지 않는다.

## 루트 통합 후 조치

README의 대표 대안 설명과 노트의 `FastF1 관측 보정 계수` 라벨을 반영했다. 이전 기록의 학습 연도를 임의로 소급 확정하지 않는다. 최종 읽기 감사에서 추가로 지적한 SC/VSC의 할인율·비용 배수 혼동, 건식 지표와 우천 미모델링의 설명 구분, 성능 요약의 장식용 `Top 3`도 수정했다. 우천 관측 UI는 별도 캐시 기반 후속 수집으로 분포·5개 비교·74건 실제 전환·결측 강수 구분을 보강했다. 최종 테스트 및 실제 브라우저 근거는 [통합 보고](09-completion.md)와 [우천 후속 보고](01-wet-followup.md)를 따른다.
